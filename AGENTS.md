# AGENTS.md

A safer replacement for sharp in Next.js: decode (untrusted) → auto-orient/rotate → resize → blur → encode. Rust core exposed to Node via napi-rs, with a sharp-like TypeScript wrapper.

## Layout

- `src/api.rs`: napi exports (`transform`, `metadata`). Internal API; validates options again.
- `src/pipeline.rs`: stage order. Resizes *before* rotating (cheaper), so `src/orientation.rs` maps targets and gravity back to the input frame. ICC → sRGB (`src/color.rs`, moxcms) runs after resizing.
- `src/decode/`: one file per format. `src/encode/`: one file per format. `src/ops.rs`: resize (fast_image_resize), embed, blur.
- `src/limits.rs`: memory limits.
- `vendor/avif-decode/`: git subtree of [avif-decode](https://github.com/kornelski/avif-decode), patched to disable rav1d's asm, use rav1d's Rust API, and take thread and frame size options. Commit upstream updates with `git subtree pull --squash`.
- `js/index.ts`: public API (compiled to `dist/` by `pnpm build:js`).
- `binding.js`, `binding.d.ts`, `blunt-image-optimization.wasi.cjs`, `wasi-worker.mjs`: generated by napi (and adjusted by `scripts/napi-build.mjs`), but committed. Native and wasm builds both regenerate all of them. CI fails if they're stale.
- `test/*.test.ts`: e2e tests (`node --test`, native type stripping).
- `scripts/napi-build.mjs`: runs `napi build` in a scratch directory, updates and locks down the WASI loaders, and copies the outputs to the root.
- `scripts/build-native.mjs`, `scripts/build-wasm.mjs`: native and wasm builds. The wasm build also checks the module's imports against an allowlist.

## Rules

- Never decode with C libraries. libwebp is only for encoding.
- Disable `default-features` and enable exact features for dependencies.
- Import with `crate::` paths, not `super::`. The only exception is `use super::*;` in `mod tests`.
- Images are always 8-bit `Luma8`/`LumaA8`/`Rgb8`/`Rgba8` after `decode::normalize`.
- Every allocation sized by input must be checked against `Limits` first.
- No timeouts or cancellation: cooperative checks couldn't reliably interrupt decoders. Bound CPU work with input-proportional limits instead (like `max_scans`).
- Errors cross into JS as `{ code, message }` result objects, not rejections (napi-rs loses custom codes on wasm). Panics must stay caught (`catch_panics`); a panic on a libuv thread aborts the process.
- Tests generate fixtures with sharp. Never commit images. Compare against sharp for parity (dimensions exactly, pixels approximately).
- Before changing CI, read `.github/AGENTS.md` (pinned SHAs, `permissions: {}`, corepack, etc).

## Why decoders are called directly

`image` doesn't expose these options, so decoders are called directly:

- **JPEG (zune-jpeg):** sets `max_scans` to 32 (default 100; each progressive scan is a full pass). A pre-scan counts raw `FF E1` byte pairs and rejects more than 4096, because zune's extended-XMP reassembly is O(n²). It counts raw bytes rather than parsing segments, so it can't disagree with zune's parser. Memory checks include progressive (or multi-scan) DCT coefficient buffers.
- **PNG:** `image` uses the full allocation budget as png's metadata limit, so a small iCCP chunk could inflate to 512 MiB. We cap metadata at 16 MiB, skip text chunks, and use `STRIP_16`.
- **GIF:** `check_frame_consistency(true)`. Otherwise a 1x1 screen can hold a 65535x65535 frame.
- **WebP:** `set_memory_limit`. Otherwise metadata chunks are allocated from declared sizes (up to 4 GiB). image-webp limits-checks the VP8X canvas, but allocates from the VP8/VP8L/ANMF frame headers, so we check that the first frame matches the canvas. Known gap: VP8L Huffman tables aren't bounded.
- **AVIF (vendored avif-decode → avif-parse + rav1d):** rav1d is a git dependency on an unreleased revision for its Rust API. Its `dav1d_*` C API is `extern "C"`, so a panic there (rav1d panics on some invalid input) aborts the process. avif-decode catches panics before closing the rav1d context, because a second panic while unwinding would abort. One thread (decoding happens on the calling thread, nothing is spawned on wasm), `frame_size_limit` from the sequence header, and the decoded size must match it. A pre-scan walks the OBUs the way rav1d does and rejects more than 8 frame headers per item: each frame (even a few-byte `show_existing_frame`) is a full decode. Known gaps: avif-parse pre-allocates from declared box sizes and entry counts (bounded only by `try_reserve`), and rav1d logs errors to stderr (`rust_api::Settings` can't disable its logger).
- **TIFF:** still decoded through `image`. A pre-scan rejects JPEG compression (6/7): each tile gets an unbounded JPEG decoder, and tiles can share one tiny JPEG. It also checks tile area against the memory limit.

## Encoders

`encode::bytes_per_pixel` estimates each encoder's working memory. The numbers are measured (peak RSS on noisy 16 MP images), so re-measure when changing encoders or their settings.

## Commands

```sh
pnpm build:debug && pnpm test        # native
cargo test && pnpm lint              # unit tests, fmt, clippy, tsc
WASI_SDK_PATH=... pnpm build:wasm && pnpm test:wasi
```

## Gotchas

- **wasm:** napi uses wasi-sdk to compile libwebp and to link. wasi-sdk 34 changed wasi-libc's ABI (futex signatures, removed `__wasi_init_tp`), so it needs Rust 1.100 or later, whose bundled wasi-libc and crt match. Older Rust fails to link or instantiate.
- **WASI loaders:** napi's templates grant the host filesystem and `process.env`, and `scripts/napi-build.mjs` patches them out. Never run `napi build` directly in the repo root, which can regenerate them unpatched (if a `.wasi.d.cts` is left over from a wasm build). On its own, a native build also keeps the loaders' old export list.
- **emnapi:** pinned to `2.0.0-alpha.6`. emnapi 1.x lacks the needed archives, and `2.0.0-beta.1` is incompatible with `@napi-rs/wasm-runtime` 1.2.5.
- **Linux CI:** builds use cargo-zigbuild (glibc 2.28, matching Node). `--use-napi-cross` ships GCC 4.8, which can't build mimalloc.
- **Dead code:** test builds don't register napi exports, so `lib.rs` allows dead code under `cfg(test)`.
